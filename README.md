# Automation of CI/CD Pipeline for a Django Web Application

An end-to-end CI/CD pipeline that builds a Python/Django web application, containerizes it with Docker, and deploys it to a self-managed Kubernetes cluster running on AWS EC2 — fully automated through Jenkins.

**Application repo:** [devops-django-cicd-pipeline](https://github.com/mithunku060/devops-django-cicd-pipeline)
**Build output screenshots:** [output_screenshots](https://github.com/mithunku060/devops-django-cicd-pipeline/tree/main/output_screenshots)

---

## Architecture Overview

```
GitHub (source) ─▶ Jenkins (build/CI) ─▶ Docker Hub (image registry) ─▶ Kubernetes (deploy)
                        │
                        ├── Docker image build & push
                        └── kubectl apply (via Kubernetes credentials + plugins)
```

**Infrastructure:**
| Node | Instance Type | OS | Role |
|------|---------------|-----|------|
| Project2-master | c7i-flex.large | Ubuntu 24.04 | Jenkins, Docker, Kubernetes control plane |
| Project2-worker | c7i-flex.large | Ubuntu 24.04 | Kubernetes worker node |

---

## Tech Stack

- **Application:** Python / Django
- **Source Control:** GitHub
- **CI/CD:** Jenkins (Pipeline, Pipeline Stage View plugin, Kubernetes plugins)
- **Containerization:** Docker
- **Container Registry:** Docker Hub
- **Orchestration:** Kubernetes (kubeadm v1.30.2, containerd runtime, Weave CNI, 2-node cluster)
- **Cloud:** AWS EC2

## AWS EC2 Setup

Two EC2 instances (`Project2-master`, `Project2-worker`) were provisioned, sharing a single security group with the following inbound rules:

| Port | Protocol | Source | Purpose |
|------|----------|--------|---------|
| 22 | TCP | 0.0.0.0/0 | SSH |
| 80 | TCP | 0.0.0.0/0 | HTTP |
| 443 | TCP | 0.0.0.0/0 | HTTPS |
| 8080 | TCP | 0.0.0.0/0 | Jenkins UI |
| 8000 | TCP | 0.0.0.0/0 | Django dev server / Gunicorn |
| 6443 | TCP | 0.0.0.0/0 | Kubernetes API server |
| 2379-2380 | TCP | 0.0.0.0/0 | etcd server/client API |
| 10250 | TCP | 0.0.0.0/0 | Kubelet API |
| 10257 | TCP | 0.0.0.0/0 | kube-controller-manager |
| 10259 | TCP | 0.0.0.0/0 | kube-scheduler |
| 30000-32767 | TCP | 0.0.0.0/0 | NodePort range (app exposure) |
| 6783 | TCP | 0.0.0.0/0 | Weave CNI control plane |
| 6783 | UDP | 0.0.0.0/0 | Weave CNI fast datapath |
| 6784 | UDP | 0.0.0.0/0 | Weave CNI metrics |

> **Note:** all rules above are currently open to `0.0.0.0/0` for testing purposes. For a production-style setup, restrict SSH (22) to your own IP, and scope the Kubernetes-internal ports (6443, 2379-2380, 10250, 10257, 10259, 6783, 6784) to the security group itself so only cluster nodes can reach them — only 22, 80, 443, 8080, and the NodePort range genuinely need to stay public.

## Setup Steps

### 1. Base OS update (both nodes)
Connected to `Project2-master` as root:
```bash
sudo apt update
sudo apt upgrade
```

### 2. Install Jenkins (master node)
```bash
sudo apt update
sudo apt install fontconfig openjdk-21-jre
java -version

sudo wget -O /etc/apt/keyrings/jenkins-keyring.asc \
  https://pkg.jenkins.io/debian-stable/jenkins.io-2026.key

echo "deb [signed-by=/etc/apt/keyrings/jenkins-keyring.asc]" \
  https://pkg.jenkins.io/debian-stable binary/ | sudo tee \
  /etc/apt/sources.list.d/jenkins.list > /dev/null

sudo apt update
sudo apt install jenkins
```
Jenkins UI is then available at `http://<master-ip>:8080`.

### 3. Install Docker (master node)
```bash
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

sudo docker run hello-world
systemctl status docker
```

### 4. Install Kubernetes (both nodes)
Followed [Aareez01/kubernetes-v1.30.2-cluster-using-kubeadm](https://github.com/Aareez01/kubernetes-v1.30.2-cluster-using-kubeadm), using **containerd** as the container runtime and **Weave** as the CNI plugin:
- Run steps 1–9 on **both** master and worker.
- Run the first command of step 10 on **both** nodes; run the cluster-init command on the **master only**.
- Copy the `kubeadm join` command generated by the master and run it on the **worker**.
- Run any remaining commands (e.g. applying the Weave CNI manifest) on the **master only**.
- Verify with:
  ```bash
  kubectl get nodes
  ```
  Both `Project2-master` and `Project2-worker` should show as `Ready`.

### 5. Configure Jenkins
- Access Jenkins at `http://<master-ip>:8080` and complete initial setup.
- Add **GitHub**, **Docker Hub**, and **Kubernetes** (via kubeconfig file) credentials under **Manage Jenkins → Credentials → Global domain**.
- Install plugins: **Pipeline Stage View**, and the **Kubernetes** plugin set (4 plugins).

### 6. Give Jenkins permission to run Docker
```bash
sudo usermod -aG docker jenkins
sudo reboot
```

### 7. Dockerfile
```dockerfile
FROM python:3.9
WORKDIR /app/backend
COPY requirements.txt /app/backend
RUN pip install -r requirements.txt
COPY . /app/backend
EXPOSE 8000
CMD python /app/backend/manage.py runserver 0.0.0.0:8000
```

### 8. Jenkinsfile
The pipeline (stored in the repo as `Jenkinsfile`) runs the following stages:

1. **code cloning** — clones the `main` branch from the [application repo](https://github.com/mithunku060/devops-django-cicd-pipeline) using the `gitHub` Jenkins credential.
2. **Build** — builds the Docker image: `docker build -t my-note-app .`
3. **docker push** — tags and pushes the image to Docker Hub using the `dockerHub` credential: `docker push <docker_user>/my-note-app:latest`
4. **Deploy to kubernetes** — using the `Kubern8` kubeconfig credential:
   - `kubectl delete --all pods` (clears existing pods before redeploying)
   - `kubectl apply -f deployment.yaml`
   - `kubectl apply -f service.yaml`

```groovy
pipeline{
    agent any
    stages{
        stage("code cloning"){
            steps{
                echo "code cloned from github"
                git branch: 'main', credentialsId: 'gitHub', url: 'https://github.com/mithunku060/devops-django-cicd-pipeline'
            }
        }
        stage("Build"){
            steps{
                echo "Building image from Dockerfile"
                sh "docker build -t my-note-app ."
            }
        }
        stage("docker push"){
            steps{
                echo "Pushing image to dockerhub"
                withCredentials([usernamePassword(credentialsId: 'dockerHub', passwordVariable: 'docker_pass', usernameVariable: 'docker_user')]){
                    sh "docker tag my-note-app ${env.docker_user}/my-note-app:latest"
                    sh "docker login -u ${env.docker_user} -p ${env.docker_pass}"
                    sh "docker push ${env.docker_user}/my-note-app:latest"
                }
            }
        }
        stage("Deploy to kubernetes"){
            steps{
                        withKubeConfig(caCertificate: '', clusterName: '', contextName: '', credentialsId: 'Kubern8', namespace: '', restrictKubeConfigAccess: false, serverUrl: '') {
                        sh "kubectl delete --all pods"
                        sh "kubectl apply -f deployment.yaml"
                        sh "kubectl apply -f service.yaml"
                        }
            }
        }
    }
}
```

### 9. Kubernetes manifests

**deployment.yaml** — runs 3 replicas of the app container, pulling the image pushed to Docker Hub:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: todo-deployment
  labels:
    app: todo-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: todo-app
  template:
    metadata:
      labels:
        app: todo-app
    spec:
      containers:
      - name: todo-app
        image: mkumar060/my-note-app
        ports:
        - containerPort: 8000
```

**service.yaml** — exposes the deployment as a NodePort service, mapping external port 80 to the container's 8000:
```yaml
kind: Service
apiVersion: v1
metadata:
  name: todo-service
spec:
  ports:
    - port: 80
      targetPort: 8000
  selector:
    app: todo-app
  type: NodePort
```

### 10. Create and run the Jenkins job
- Created a new Jenkins job named **`project3`**.
- Selected **Pipeline** job type → **Pipeline script from SCM** → pointed to the GitHub repo containing the `Jenkinsfile`.
- Ran the build — pipeline completed successfully.
- Build results captured in [`output_screenshots`](https://github.com/mithunku060/devops-django-cicd-pipeline/tree/main/output_screenshots).

## Accessing the Application

The `todo-service` Service maps external port `80` to the container's port `8000` and is exposed as a `NodePort`. Once deployed, the app is reachable via any cluster node's public IP and the auto-assigned NodePort (in the `30000-32767` range — check with `kubectl get svc todo-service`):
```
http://<node-public-ip>:<node-port>
```

## Notes / Possible Improvements

- Tighten security group rules — scope SSH to your IP and restrict Kubernetes-internal ports to the security group itself rather than `0.0.0.0/0`.
- Add automated tests as a pipeline stage before the build/deploy stages.
- Add a container image scanner (e.g. Trivy) as a pipeline stage before pushing to Docker Hub.
- Move Kubernetes manifests into a dedicated `k8s/` directory and consider managing them via a Helm chart for reusability.
- Consider using Jenkins credentials binding with least-privilege Kubernetes RBAC rather than a full-admin kubeconfig.
